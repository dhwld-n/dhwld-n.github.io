PROJECT DEMO

LLM 기반 타겟 보드 테스트 자동화 파이프라인

머신러닝 추론 워크로드를 여러 종류의 타겟 보드에서 테스트하는 과정을 git push 한 번으로 자동화합니다. 그중 에이전트가 워크로드를 분석해 테스트 보드를 고르는 단계를 아래에서 직접 실행해 볼 수 있습니다.

감바랩스(Gamba Labs) 인턴십 2026.07 – 08 Python · LLM · GitHub Actions

파이프라인

.github/workflows/test.yml — on: push, self-hosted 러너에서 실행.

1 · 보드 선택 LLM이 커밋·테스트 코드를 읽고 워크로드를 분석해 유휴 보드 중 적합한 것을 선택
2 · 배포·실행 연결 방식(SSH·시리얼·로컬)별 엔진으로 보드에 코드를 올려 테스트 실행
3 · 회귀 판정 정확도가 기준 이상 떨어지면 파이프라인 실패 처리 → 병합 차단
4 · 기록·알림 결과를 Notion에 기록, Teams로 알림

데모 · 에이전트가 보드를 고르는 과정

응답은 미리 준비한 예시입니다 (실제 assign_board.py의 프롬프트·출력 형식 기준)

성능 회귀 게이트

          
직전 실행 대비 정확도가 기준(8%p) 이상 떨어지면 파이프라인을 exit 1로
             실패시켜 병합을 차단합니다. 회귀가 잡히면 LLM이 원인 코드를 자동 진단하고
             과거 회귀와 패턴을 비교합니다.

        

        

          
자연어 인터페이스

          
"이번 주 정확도 제일 높았던 조합이 뭐야?" 같은 질문에 답하고, .docx
             보고서도 자연어로 생성합니다. 수치·통계는 코드가 계산하고 LLM은 서술만 담당합니다.

        

        

          
엔진 분리

          
보드 연결 방식별로 실행 엔진을 동일 인터페이스로 통일. 새 보드 타입 추가 =
             엔진 파일 하나 + 매핑 한 줄.

        

        

          
LLM 추상화

          
모든 모델 호출을 단일 모듈로 통일. 기본값은 Gemini Flash(무료 티어)이고,
             환경변수(LLM_BASE_URL, LLM_MODEL_NAME)로 OpenAI·로컬 모델로 교체 가능.
